> ### 🔄 SRS v3.0 반영 — 이 태스크에서 바뀐 것 *(2026-09-01)*
> 🔴 **후보의 출처와 개수가 바뀌었다** — v2.2는 *"원본 탐지 결과를 약 30개로 좁힌다"* 였다. v3.0에서 **후보 = F25가 자른 클립**이고, 🔴 **개수는 프롬프트가 정한다**(PRD G15 · Q19). 정렬 기준도 "온전도"에서 **`trackStatus` + 정상 구간 비율**로 바뀐다. **전면 재작성**.
>
> **기준 문서**: `SRS/[SRS]hilit-SRSv2.0-nextjs.md` **v3.0 §5.1 ②** · `PRD/HILiT_PRD_v0_2.md` F3 · **G15**

> 🔀 **FR-031(후보 조회) · FR-013(Gemini 보조 경로)을 흡수했다** *(축약 2026-08-30)* — 두 ID는 폐번이며 이 문서를 가리킨다. 🔄 **v3.0에서 FR-013의 "Gemini 보조 경로"는 FR-037(프롬프트 컷)의 본체가 되어 이 태스크를 떠났다.**

> 🔀 **FR-009(ConfidenceGate 제외)를 흡수했다** *(축약 2026-09-01)* — 제외 판정의 출력이 **`trackStatus` 필드 하나**이고 그 값을 쓰는 곳이 후보 목록뿐이다. **같은 데이터·같은 화면**이므로 나뉘어 있으면 "제외했는데 목록에 남았다" 같은 어긋남이 두 태스크 사이에 생긴다. `FR-009` 는 폐번이며 이 문서를 가리킨다.

> ### ⚠️ 이 태스크에는 수렴형 축이 하나 섞여 있다 *(← FR-009)*
> 후보 산출·정렬·조회는 **구현하면 끝나는 일**이다. 그러나 **ConfidenceGate의 임계 `τ` 는 다르다** — 코드가 동작하는 것과 τ가 옳은 것은 다르고, **τ는 FR-045의 실측 오인식률이 나와야 정해진다.**
>
> 🔴 **완료 판정을 둘로 나눈다** — ① 산출·정렬·조회는 **스프린트 트랙** ② **τ 확정은 Gate A 측정 주기**에 붙인다(SRS §4.4). 하나로 묶으면 이 태스크가 매 스프린트 "미완"으로 이월된다.

## 🎯 Summary
- 기능명: **[FR-012] 트래킹이 끝난 클립을 판단하기 좋은 순서로 보여준다**
- 목적: **사용자가 "이 구간이 맞는가"를 빠르게 판단할 수 있게 만든다.**

> 🔴 **"약 30개"는 죽은 숫자다.** VPS 0.3의 30개는 **원본 전체 탐지를 전제**한 값이었다. 컷이 앞에 서면 *"슛 쏘는 장면"* 은 5개, *"내가 나온 장면 전부"* 는 40개가 나온다. **개수를 상수로 박으면 프롬프트가 무의미해진다.**
>
> 🔺 **Q19가 미결이다.** 그전까지 **상한만 두고 하한은 두지 않는다** — 적게 나오는 것은 프롬프트의 결과이고, 많이 나오는 것은 UI 부담이다.

> 🔴 **정렬 기준이 "볼 만한가"가 아니라 "추적이 온전한가"다.** *"이 구간이 볼 만한가"* 는 이미 F25가 판정했다(`matchScore`). 이 태스크가 더하는 정보는 **"이 클립에서 당신을 제대로 따라갔는가"** 이며, 그것이 `trackStatus` 다.

> 🔴 **복구 여부를 숨기지 않는다.** `RECOVERED` 를 `NORMAL` 과 같게 보이면 사용자는 **서버가 개입한 구간을 알 수 없다.** PRD AF-4가 요구하는 것은 저신뢰 제외만이 아니라 **상태의 가시화**다.

> 🔴 **저신뢰는 "표시"가 아니라 "제외"다** *(← FR-009)*
>
> REQ-FUNC-027은 명시적으로 *"저신뢰 표시로 사용자에게 판단을 넘기지 않는다"* 고 못박았다. **저신뢰 배지를 달아 목록에 남기는 구현은 요구 위반**이다. `LOW_CONFIDENCE` 는 **내부 판정값**이지 사용자에게 보여주는 배지가 아니다.
>
> 🔴 **그리고 이 결정에는 대가가 있다** — 제외는 **Gate A의 추적 유지율을 깎는다.** REQ-FUNC-003이 **제외 후** 값으로 판정하는 이유가 여기에 있다. **정확도와 재현율을 맞바꾸는 손잡이가 τ 하나이며, 이 태스크가 그 손잡이를 쥔다.**

## 🧪 Acceptance Criteria (BDD/GWT)

**Scenario 1: 후보 개수가 프롬프트를 따른다** *(G15)*
- **Given**: *"슛 쏘는 장면"* 으로 5개, *"내가 나온 장면 전부"* 로 40개가 잘림
- **When**: 각각 후보 목록을 조회함
- **Then**: 🔴 **5개와 40개가 그대로 나온다.** 30개로 맞추려고 자르거나 채우지 않는다

**Scenario 2: 상한이 UI를 보호한다**
- **Given**: 컷 결과가 상한을 초과
- **When**: 후보를 산출함
- **Then**: **상한까지만 제시**되고 잘린 사실이 계측된다. 🔺 상한값은 Q19 결정 전까지 설정값이다

**Scenario 3: 복구된 구간이 구분되어 보인다** *(AF-4)*
- **Given**: 복구를 거친 클립
- **When**: 후보 목록을 조회함
- **Then**: 🔴 **`trackStatus = RECOVERED` 로 표시된다.** 정상과 같게 보이면 사용자가 서버 개입을 알 수 없다

**Scenario 4: 추적이 온전한 클립이 위에 온다**
- **Given**: 정상 구간 비율이 각각 100% · 60% 인 두 클립
- **When**: 정렬함
- **Then**: **100%가 위에 온다.** *"볼 만한가"* 는 F25가 이미 판정했고, 여기서 더하는 정보는 **추적 온전도**다

**Scenario 5: 목록이 1초 안에 뜬다** *(REQ-NF-005)*
- **Given**: 후보 40개
- **When**: 목록을 조회함
- **Then**: **p95 ≤ 1초.** 썸네일은 저해상도이고 가상 스크롤을 쓴다

**Scenario 6: 컷 실패와 추적 실패가 다르게 안내된다**
- **Given**: ① 프롬프트에 맞는 구간 0건 ② 클립은 있으나 전부 추적 실패
- **When**: 후보 화면에 진입함
- **Then**: 🔴 **①은 프롬프트 수정 경로(AF-3), ②는 수동 트래킹 경로(AF-13).** 같은 빈 화면을 보여주면 사용자가 무엇을 고쳐야 할지 모른다

**Scenario 4-b: 갈 수 없는 곳으로 안내하지 않는다** *(v0.4 · AF-16)*
- **Given**: 전 클립 추적 실패(AF-13) · 🔴 **무료 사용자이고 이번 달 수동 트래킹을 이미 씀**
- **When**: 후보 화면에 진입함
- **Then**: 🔴 **"수동 트래킹으로 계속하기"가 뜨지 않는다.** 대신 **리프레이밍 없이 합치기 · 갱신일 · 결제**가 제시된다(AF-16) — 🔴 **잔여를 보지 않고 AF-13 문구를 고정으로 쓰면 사용자는 막힌 문으로 안내된다**

**Scenario 7: 저신뢰가 조용히 섞이지 않는다** *(REQ-FUNC-027)*
- **Given**: `reidScore` 가 임계 미만인 클립
- **When**: 목록을 조회함
- **Then**: 🔴 **`LOW_CONFIDENCE` 로 표시되거나 제외된다.** 타인의 장면이 내 하이라이트로 조용히 들어오면 신뢰가 즉시 깨진다(R2)

**Scenario 8: 임계 미만이 목록에서 사라진다** *(← FR-009 · SC-1.F5)*
- **Given**: CT-007 픽스처 **M2**(12구간 중 4개가 임계 미만)
- **When**: ConfidenceGate를 통과시킴
- **Then**: 🔴 **4건이 후보 목록에 없다.** `excluded_reason` 이 기록되고 제외 건수가 계측된다

**Scenario 9: 저신뢰 표시로 대체하지 않는다** *(← FR-009 · REQ-FUNC-027)*
- **Given**: 임계 미만 클립
- **When**: 후보 목록 응답을 확인함
- **Then**: 🔴 **사용자에게 노출되는 `LOW` 배지 항목이 없다.** 판단을 사용자에게 넘기는 구현은 요구 위반이다 — Scenario 7의 `LOW_CONFIDENCE` 는 **내부 판정값**이다

**Scenario 10: 무표시 혼입이 0건이다** *(← FR-009 · REQ-FUNC-027)*
- **Given**: 정답셋에서 타인이 등장하는 구간
- **When**: 후보 목록을 검사함
- **Then**: 🔴 **타인의 장면이 표시 없이 섞인 사례가 0건.** *"거의 없다"* 는 통과가 아니다

**Scenario 11: 제외가 사유 안내로 이어진다** *(← FR-009 · SC-1.F6)*
- **Given**: 픽스처 **M5**(제외 후 후보 1개)
- **When**: 후보 화면을 엶
- **Then**: 🔴 **빈 목록만 보여주지 않는다.** *"왜 후보가 적은지"* 가 `excludedCount` 와 함께 전달된다

**Scenario 12: 신뢰도가 없으면 조용히 통과시키지 않는다** *(← FR-009 · M3)*
- **Given**: `reidScore === null`
- **When**: 게이트를 실행함
- **Then**: 🔴 **제외를 수행하지 않고 그 사실이 명시적으로 드러난다.** 🔴 **`null` 을 0으로 보면 전량 제외되고, 1로 보면 전량 통과된다 — 둘 다 틀리다**

**Scenario 13: τ 를 코드 배포 없이 조정할 수 있다** *(← FR-009)*
- **Given**: FR-045의 실측 오인식률
- **When**: τ 를 조정함
- **Then**: 🔴 **코드 변경 없이 반영된다.** Gate A와 오인식률의 균형점은 **한 번에 맞지 않으므로** 반복 조정이 전제다

**Scenario 14 (실패): τ 를 올려 Gate A를 통과시키지 않는다** *(← FR-009)*
- **Given**: Gate A 미달 상황
- **When**: τ 조정을 검토함
- **Then**: 🔴 **τ 를 올리면 제외가 늘어 제외 후 유지율이 더 떨어진다.** 게이트가 이 방향의 조작에 저항하도록 설계되어 있다. **τ 하향은 오인식률 실측이 여유를 보일 때만 정당하다**

**Scenario 15 (실패): 개수를 맞추려고 클립을 쪼개지 않는다**
- **Given**: 후보가 3개뿐인 결과
- **When**: "너무 적다" 는 판단
- **Then**: 🔴 **쪼개서 개수를 늘리지 않는다.** 3개는 프롬프트가 정확했다는 뜻일 수 있다 — 개수는 품질 지표가 아니다

## ⚙️ Technical & Non-Functional Constraints
- 🔴 **개수 상수를 코드에 박지 않는다** — Q19 결정 전까지 설정값
- 🔴 **`matchScore` 와 `reidScore` 를 정렬에서 섞지 않는다** — 다른 질문에 답하는 값이다
- 🔴 **RSC 직접 조회** — Server Action을 거치지 않는다(읽기)
- 🔺 **썸네일 생성 위치 `[TBD]`** — 서버 인코딩 불가(A-T1)이므로 브라우저 생성 또는 Storage 변환 검토
- 🔺 **상한 초과 시 UX** — "더 보기" vs 잘라내기 미정. UX-002 소관
- 후보 산출은 멱등해야 한다 — 재진입 시 중복 INSERT 금지
- 🔴 **τ 는 `[TBD]`** *(← FR-009)* — 초기값은 FR-045가 측정한 **오인식률 ≤ 2%를 만족하는 최소 임계**. 그 실측 전에는 어떤 숫자도 근거가 없다
- 🔴 **구간 점수(`matchScore`)를 τ 에 쓰지 않는다** — *"볼 만한가"* 로 *"당신인가"* 를 판정하면 요구가 조용히 바뀐다
- 🔺 **"후보가 현저히 줄면"의 기준이 `[TBD]`** — 절대 개수인지 제외율인지 정해야 안내 트리거가 결정된다
- 제외된 클립은 **삭제하지 않고 표시만 한다** — 재판정이 가능해야 τ 조정 실험이 성립한다
