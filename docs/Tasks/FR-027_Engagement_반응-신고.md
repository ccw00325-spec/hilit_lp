## 🎯 Summary
- 기능명: **[FR-027] 나만 보는 기록에는 반응 버튼이 아예 없다**
- 목적: **기록이 SNS 콘텐츠가 아닌 상태를 UI 수준에서도 유지한다.**

> 🔴 **"권한이 없다"가 아니라 "붙지 않는다"가 요구다.**
>
> REQ-FUNC-015: *"**"나만 보기" 기록에 반응 UI가 붙어서는 안 된다**."*
>
> 반응 버튼을 두고 눌렀을 때 거부하는 구현은 요구 위반이다. **버튼이 있다는 것 자체가 "이건 남에게 보여주는 것"이라는 신호**이고, 그 신호는 D4와 충돌한다. **회색 좋아요 버튼 하나가 기록을 콘텐츠로 재정의한다.**

> 🔴 **신고는 범위 경계가 요구사항에 못박혀 있다.**
>
> REQ-FUNC-016: *"**신고 처리 절차는 미정**이므로 **접수와 이력 보존까지만** 구현한다 `[TBD]`."* 신고 대시보드·자동 숨김·제재 로직을 만들지 않는다 — 확정 전에 만든 로직은 확정 후 폐기된다.

## 🧪 Acceptance Criteria (BDD/GWT)

**Scenario 1: 비공개 기록에 반응 UI가 붙지 않는다** *(SC-6.2 · REQ-FUNC-015)*
- **Given**: `visibility = private` 인 자기 기록
- **When**: 화면을 확인함
- **Then**: 🔴 **좋아요·댓글 영역이 없다.** 있으면서 비활성인 것도 아니고 **존재하지 않는다**

**Scenario 2: 서버가 반응 가능 여부를 알려준다**
- **Given**: 기록 조회 응답
- **When**: 필드를 확인함
- **Then**: 🔴 **반응 가능 여부가 서버 판정으로 담긴다.** 클라이언트가 `visibility` 를 보고 스스로 판단하면 **판정 로직이 두 곳에 생겨 갈라진다**

**Scenario 3: 조작된 요청이 통하지 않는다** *(REQ-NF-009)*
- **Given**: 타인의 비공개 기록 ID
- **When**: 좋아요·댓글 요청을 직접 보냄
- **Then**: 🔴 **거부되고 감사 로그가 남는다.** UI 미부착은 방어가 아니다

**Scenario 4: ~~그룹 공개는 구성원만 반응한다~~** 🔴 **v3.0 삭제** *(F23 제외 · Public/Private 2단만 판정)*
- **Given**: `visibility = GROUP` 인 기록
- **When**: 비구성원이 반응을 시도함
- **Then**: **거부된다.** RLS가 기록 자체를 보여주지 않으므로 구조적으로 도달하지 않는다

**Scenario 5: 중복 좋아요가 DB에서 막힌다**
- **Given**: 이미 좋아요한 기록
- **When**: 다시 요청함
- **Then**: 토글로 취소되거나 무시된다. **부분 UNIQUE 제약이 최종 방어선**이고 **댓글은 중복이 허용된다**

**Scenario 6: 신고가 접수되고 사용자가 확인한다** *(SC-6.3)*
- **Given**: 문제가 있는 댓글
- **When**: 신고함
- **Then**: **접수되고 접수 사실이 응답으로 확인**된다. 접수 성공률 **≥ 99%**

**Scenario 7: 신고 이력이 보존된다** *(REQ-FUNC-016)*
- **Given**: 접수된 신고
- **When**: 저장을 확인함
- **Then**: 🔴 **대상 · 사유 · 시각 · 신고자가 보존**된다. **처리 절차가 확정됐을 때 소급 처리할 수 있어야 한다**

**Scenario 8: 처리 로직을 만들지 않는다** *(범위 경계)*
- **Given**: 신고가 여러 건 접수됨
- **When**: 대상 콘텐츠를 확인함
- **Then**: 🔴 **자동 숨김·제재가 일어나지 않는다.** **`[TBD]` 인 절차를 추측해 구현하지 않는다**

**Scenario 9: 접수가 이행 못할 약속을 하지 않는다**
- **Given**: 신고 접수 응답
- **When**: 문구를 확인함
- **Then**: 🔺 **"접수되었다"까지만** 말한다. *"조치하겠다"* 는 **현재 이행할 수 없는 약속**이다

**Scenario 10: 공개 → 비공개 전환 시 처리가 정의되어 있다**
- **Given**: 좋아요 12개를 받은 전체공개 기록
- **When**: 나만 보기로 바꿈(FR-020)
- **Then**: 🔺 **`[TBD]`** — 삭제인가 보존 후 비노출인가. **FR-020과 같은 미결을 공유하며 한쪽에서만 정하면 어긋난다**

**Scenario 11 (실패): 비활성 버튼으로 대체하지 않는다**
- **Given**: 구현 편의를 위한 *"회색 처리된 좋아요 버튼"* 제안
- **When**: 요구 정합성을 검토함
- **Then**: 🔴 **요구 위반이다.** *"미부착"* 이 요구 문구이며, **버튼의 존재 자체가 기록을 콘텐츠로 규정한다**

**Scenario 12 (실패): 접수 실패가 조용하지 않다**
- **Given**: 신고 저장이 실패
- **When**: 사용자 화면을 확인함
- **Then**: 🔴 **실패가 드러나고 재시도가 가능**하다. **접수됐다고 표시하고 저장이 안 된 상태가 최악**이다

## ⚙️ Technical & Non-Functional Constraints
- 🔴 **반응 가능 여부는 서버가 판정** — `VisibilityEnforcer` 의존이 §5.1에 명시돼 있다. **좋아요와 댓글이 같은 판정기를 쓴다**
- 🔴 **RLS가 도달 자체를 막는다** — 애플리케이션 검증은 이중 방어
- 🔴 **신고 처리 절차는 범위 밖** — 대시보드·자동 숨김·제재를 만들지 않는다
- 🔺 **좋아요 수 집계와 RLS** — `count(*)` 도 정책의 영향을 받으므로 **집계 값이 조회자에 따라 달라지지 않는지 확인**한다
- 🔺 **공개 전환 시 기존 반응 처리가 `[TBD]`** — FR-020과 함께 결정
- 🔺 **댓글 길이 제한 · 금지어 필터 · 알림은 요구사항에 없다** — 임의로 추가하지 않는다
- 🔺 **신고 대상 유형이 `[TBD]`** — 요구 문구는 *"댓글에 신고 기능이 포함"* 이다
