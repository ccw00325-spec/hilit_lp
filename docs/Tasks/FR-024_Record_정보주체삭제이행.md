## 🧪 Acceptance Criteria (BDD/GWT)

**Scenario 1: 6종이 전부 사라진다** *(REQ-NF-019)*
- **Given**: 파이프라인을 완주한 기록 하나
- **When**: 삭제 요구를 이행함
- **Then**: 🔴 **DB와 객체 스토리지 양쪽에서 6종이 전부 없다.** 잔존 스캔이 0건을 보고한다

**Scenario 2: 논리 삭제가 아니다** *(REQ-NF-019)*
- **Given**: 삭제 완료 상태
- **When**: DB를 직접 조회함
- **Then**: 🔴 **행이 없다.** `deleted_at` 이 채워진 행이 남아 있으면 **이 요구는 미이행이다**

**Scenario 3: 객체 스토리지에도 남지 않는다**
- **Given**: 삭제 완료 상태
- **When**: 스토리지를 직접 조회함
- **Then**: 🔴 **원본 · 중간 산출물 · 완성물 · 썸네일이 전부 없다.** **DB만 지우면 4GB 영상이 스토리지에 그대로 남는다**

**Scenario 4: 집계는 유지된다** *(REQ-NF-019)*
- **Given**: 삭제된 사용자의 계측 이벤트
- **When**: 지표를 확인함
- **Then**: 🔴 **식별자가 제거된 채 집계는 유지**된다. **이벤트를 통째로 지우면 과거 지표가 소급 변경되어 Gate 판정 근거가 사라진다**

**Scenario 5: FR-004와 결과가 다르다**
- **Given**: 같은 기록에 대해 FR-004(원본 삭제)만 실행한 경우
- **When**: 잔존을 확인함
- **Then**: 🔴 **궤적·구간·후보·완성물·기록이 남아 있다.** **두 기능은 대체 관계가 아니다**

**Scenario 6: 파기 절차 문서와 일치한다** *(NF-017 ③)*
- **Given**: 승인된 파기 절차 문서
- **When**: 구현과 대조함
- **Then**: **삭제 대상과 방법이 일치**한다. 🔴 **문서와 구현이 다르면 NF-017의 승인이 무효다**

**Scenario 7 (실패): 부분 실패가 성공으로 보고되지 않는다**
- **Given**: DB는 지워졌으나 스토리지 삭제가 실패
- **When**: 결과를 확인함
- **Then**: 🔴 **미완료로 기록되고 재시도된다.** *"거의 다 지웠다"* 는 법적 이행이 아니다

## ⚙️ Technical & Non-Functional Constraints

- 🔺 **처리 시한이 `[TBD]`** — 즉시인지 N일 이내인지. **NF-017의 파기 절차 문서가 이 값을 정한다**
- 🔺 **백업에서의 삭제가 `[TBD]`** — 요구사항이 다루지 않는다. **법무 판단이 필요한 항목으로 표면화한다**
- 되돌릴 수 없으므로 **확인 절차와 감사 로그**가 필요하다(NF-009)
