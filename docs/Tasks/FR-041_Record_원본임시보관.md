## 🧪 Acceptance Criteria (BDD/GWT)

**Scenario 1: 7일 안에는 다시 편집된다** *(AC7-5)*
- **Given**: 3일 전 업로드한 원본
- **When**: 다시 열어 다른 프롬프트로 컷을 실행함
- **Then**: 🔴 **원본이 남아 있어 재편집된다** · Gemini 1단 캐시가 살아 있으면 재사용된다

**Scenario 2: 7일이 지나면 삭제된다**
- **Given**: `retainUntil` 이 지난 원본
- **When**: Cron이 실행됨
- **Then**: **Storage에서 삭제되고 `status = EXPIRED`.** 행은 남아 이력이 보존된다

**Scenario 3: 삭제 전에 알린다** *(AC7-5)*
- **Given**: 만료 D-1
- **When**: 사용자가 앱을 열거나 알림을 받음
- **Then**: 🔴 **"내일 원본이 삭제됩니다" 가 안내된다.** 예고 없는 삭제는 신뢰를 깬다

**Scenario 4: 완성한 기록은 남는다**
- **Given**: 원본이 만료된 프로젝트
- **When**: 마이페이지를 확인함
- **Then**: 🔴 **완성 영상(`Record`)은 그대로 있다.** 원본 만료가 결과물을 지우면 D4(기록이 남는다)가 깨진다

**Scenario 5: 무료 플랜은 보관하지 않는다**
- **Given**: 무료 사용자
- **When**: 편집 완료 후 다음 날 다시 열어봄
- **Then**: **원본이 없다.** 보관은 유료 혜택이며 CT-010 상수가 이를 정한다

**Scenario 6: 정보주체 삭제는 7일을 기다리지 않는다**
- **Given**: 사용자의 삭제 요구(FR-024)
- **When**: 삭제를 실행함
- **Then**: 🔴 **`retainUntil` 과 무관하게 즉시 삭제**된다. 보관 정책이 삭제권을 지연시키면 안 된다

**Scenario 7 (실패): 만료를 조용히 처리하지 않는다**
- **Given**: 배치가 대량 삭제를 수행
- **When**: 로그·계측을 확인함
- **Then**: 🔴 **`source_expired` 가 건수·용량과 함께 남는다.** 스토리지 원가 추적의 입력이다

- 🔴 **행은 남기고 객체만 삭제** — 이력·감사 추적 보존
- 🔺 **파생물 만료 범위 `[TBD]`** — 클립·Gemini 캐시·추적 궤적 중 어디까지인가. 재편집 실익과 스토리지 원가의 교환

- 보관 기간은 **CT-010 상수** — 코드에 7을 박지 않는다
