## 🧪 Acceptance Criteria (BDD/GWT)

**Scenario 1: 선택 없이 결과물이 만들어지지 않는다** *(SC-3.3)*
- **Given**: 사용자가 아무 후보도 선택하지 않음
- **When**: 확정을 시도하거나 시간이 경과함
- **Then**: 🔴 **결과물이 생성되지 않는다.** 자동 확정 **0건**

**Scenario 2: 미리 체크된 후보가 없다** *(REQ-FUNC-005)*
- **Given**: 후보 목록을 처음 열었을 때
- **When**: 선택 상태를 확인함
- **Then**: 🔴 **선택된 항목이 0개다.** *"추천 5개 자동 선택"* 은 명시적 선택이 아니다 — **사용자가 그대로 확정하면 시스템이 고른 것이 된다**

**Scenario 3: 후보가 하나여도 자동 선택하지 않는다**
- **Given**: 제외 후 후보가 1개만 남음(SC-1.F6 상황)
- **When**: 화면에 진입함
- **Then**: 🔴 **여전히 사용자가 눌러야 한다.** 후보 개수가 D2를 면제하지 않는다

**Scenario 4: 모든 후보에 선택·제외가 가능하다** *(REQ-FUNC-005)*
- **Given**: 제시된 후보 전체
- **When**: 각각을 선택하거나 제외함
- **Then**: **100% 전부에 대해 가능**하다. 시스템이 *"이건 고르면 안 된다"* 고 막는 후보가 없다

**Scenario 5: 다시 고르기가 선택을 지우지 않는다** *(SC-3.F2)*
- **Given**: 5개를 선택하고 확정해 리프레이밍 결과를 봄
- **When**: 다시 고르기로 복귀함
- **Then**: 🔴 **기존 선택 5개가 그대로 있다.** 선택 상태 유실 **0건** · `reselection_started` 발행

**Scenario 6: 남의 후보를 확정할 수 없다**
- **Given**: 타인 소유 원본의 `candidateIds`
- **When**: 확정을 시도함
- **Then**: 거부된다

**Scenario 7 (실패): 편의 기능이 D2를 우회하지 않는다**
- **Given**: *"전체 선택"* 버튼 같은 편의 기능 제안
- **When**: 요구 정합성을 검토함
- **Then**: 🔴 **사용자가 누르는 전체 선택은 허용**된다(명시적 조작이다). **시스템이 미리 선택해두는 것은 불가**하다. **경계는 "누가 눌렀는가"이며 "몇 개인가"가 아니다**

## ⚙️ Technical & Non-Functional Constraints
- 🔴 **자동 확정 차단은 서버에서 강제한다** — UI에서만 막으면 조작된 요청으로 우회된다
- 🔴 **선택 상태를 서버에 저장하는 이유는 SC-3.F2다** — 웹에서는 탭 종료로 클라이언트 상태가 사라진다(v2.2 §6.5.3). **선택은 서버에, 렌더는 클라이언트에**
- 🔺 **선택 상한이 `[TBD]`** — 30개 후보 전부를 선택하면 결과물 길이가 15초를 크게 넘는다. **음악 자동 맞춤(REQ-FUNC-007)이 15초 기준이므로 상한 정의가 필요하다**
- `selection_confirmed` 에 **실험군을 담는다** — Q7(후보 개수) 실측의 짝이 되는 이벤트다
