> ### 🆕 SRS v3.0에서 신설 *(2026-09-01)*
> PRD v0.2 ADR-2가 복구·리프레이밍을 **"Hilit GPU Server(Cutie)"** 에 뒀다. 문구 그대로면 **자사 GPU 서버**이고 이는 **C-TEC-005(자체 서버 구축 없이)·A-T4와 정면 충돌**한다. 이 스파이크가 **T5**를 푼다.
>
> **기준 문서**: `SRS/[SRS]hilit-SRSv2.0-nextjs.md` **v3.0 §2.2 ② · §2.4 T5 · §9-1**

> ### ⚠️ 이것은 개발 태스크가 아니다
> 산출물은 **① PRD 문구 확인 ② 공급자 비교표 ③ T5 결정문**이다. 결정이 없으면 §7.4 설계가 가설로 남는다.

## 🎯 Summary
- 기능명: **[SP-004] 복구를 어디서 돌릴지 정하고, 그것이 제약을 위반하는지 판정한다**
- 목적: **C-TEC-005를 지킬 수 있는 구현 경로를 확정한다.**

> 🔴 **먼저 문구를 확인해야 한다.** PRD의 *"Hilit GPU Server"* 가
> - **논리적 이름**(브랜드상 우리 서비스의 일부)이면 → **G1(관리형 추론 서비스)** 로 구현하고 C-TEC-005는 그대로다
> - **자사 인프라**를 뜻하면 → **C-TEC-005를 개정**해야 한다
>
> **이 확인 없이 공급자를 고르면 나중에 전제가 바뀐다.**

> 🔴 **G3(복구 없이 단말 결과만)은 선택지가 아니다.** PoC §7.3: **모바일 재획득(Lv2)이 한 번도 성공하지 못했다.** 복구를 빼면 실패 구간이 그대로 남고 O9(추적 유지율 85%)에 닿지 못한다.

## 🧪 Acceptance Criteria (BDD/GWT)

**Scenario 1: 문구 확인이 먼저 끝난다**
- **Given**: PRD의 "Hilit GPU Server" 표현
- **When**: 스파이크를 시작함
- **Then**: 🔴 **공급자 조사보다 문구 확인이 먼저다.** 자사 인프라라면 조사 자체가 무의미하다

**Scenario 2: C-TEC-005 판정이 명시된다**
- **Given**: 채택안
- **When**: 결정문을 확인함
- **Then**: 🔴 **"C-TEC-005 유지" 또는 "개정 필요"** 가 문장으로 적혀 있다. 판정을 흐리면 나중에 아무도 책임지지 않는다

**Scenario 3: 콜드 스타트가 측정된다**
- **Given**: 후보 서비스
- **When**: 산발적 호출을 재현함
- **Then**: 🔴 **모델 로딩 포함 첫 호출 지연이 나온다.** 이 값이 SRS §5.1의 "복구 1회 p95 ≤ 90초"를 좌우한다

**Scenario 4: 원가가 실기기 기준으로 다시 나온다**
- **Given**: PoC의 MX250 실측 10~17원
- **When**: 채택 서비스에서 재측정함
- **Then**: **호출당 실제 과금이 나온다.** PRD §5.5의 상한 계산이 이 값으로 갱신된다

**Scenario 5: 데이터 처리 조건이 게이트와 대조된다**
- **Given**: 공급자의 데이터 보관·학습 이용 약관
- **When**: NF-017 5번째 산출물과 대조함
- **Then**: 🔴 **영상이 학습에 쓰이거나 장기 보관되면 게이트를 통과하지 못한다.** 원가만 보고 고르면 여기서 막힌다

**Scenario 6 (실패): 복구를 빼는 안을 채택하지 않는다** *(G3)*
- **Given**: "원가를 아끼려면 복구 없이" 라는 검토
- **When**: PoC §7.3을 확인함
- **Then**: 🔴 **모바일 재획득이 한 번도 성공하지 못했다.** 복구가 없으면 실패 구간이 그대로 남아 **O9에 닿지 못한다**
