> ### 🔄 SRS v3.0 반영 — 이 태스크에서 바뀐 것 *(2026-09-01)*
> 🔴 **플로우 순서 정정 + 단계 추가** — 기존 `원본 선택 → 후보 선택 → 구도 확인 → 음악` 앞에 **① 프롬프트 컷(UX-011)** 이 들어가고, 뒤에 **자막(UX-013)** 이 붙는다. 새 순서: **업로드 → 프롬프트 컷 → 대상 지정 → 추적 대기 → 후보 선택 → 합치기 → 음악 → 자막 → 저장**. 🔴 **리프레이밍은 별도 단계가 아니다** — Cutie 복구 단계에서 크롭 경로가 나오고 선택 후 자동 적용된다.
>
> **기준 문서**: `SRS/[SRS]hilit-SRSv2.0-nextjs.md` **v3.0** · `PRD/HILiT_PRD_v0_2.md`

> ### 🔴 SRS v3.3 반영 — 무료 플로우의 트래킹 단계가 조건부가 됐다 *(2026-09-02)*
> PRD **v0.4**: 수동 트래킹이 **무료 월 1회**가 됐다(구독 무제한). 🔴 **무료 사용자의 플로우에서 "추적" 단계가 항상 있는 것이 아니게 된다.**
>
> | 무료 사용자 | 플로우 |
> | --- | --- |
> | 트래킹 잔여 있음 | 업로드 → 수동 컷 → **수동 트래킹** → 선택 → 합치기 → 음악 → 자막 → 저장 |
> | 🔴 **잔여 없음** | 업로드 → 수동 컷 → 🔴 **(트래킹 건너뜀 · AF-16 안내)** → 선택 → 합치기 → 음악 → 자막 → 저장 |
>
> 🔴 **건너뛴 플로우도 "완성"으로 끝나야 한다.** 리프레이밍만 빠진 결과물이 나온다 — **중단이 아니라 분기다**(PRD AF-16).
>
> 🔴 **한도 판정은 트래킹 도구 *진입 전에* 한다.** 키프레임을 다 찍은 뒤 저장 시점에 막으면 **사용자가 한 노동이 통째로 버려진다**(FR-038).
>
> 🔺 **단계 표시기(progress indicator)가 이 분기에서 어긋난다** — 5단계 중 4번째를 건너뛰면 *"3 → 5"* 로 점프한다. **단계 수를 사용자별로 계산하거나, 건너뛴 단계를 회색으로 남기고 이유를 붙인다.**
>
> 🔺 **첫 달 5회 · 이후 2회의 비대칭도 이 화면에 닿는다** — 업로드 진입점에서 **트래킹 잔여를 함께** 보인다(UX-012). *"5편 올렸는데 트래킹은 1편"* 을 나중에 알게 하지 않는다.
>
> **기준 문서**: `SRS/[SRS]hilit-SRSv2.0-nextjs.md` **v3.3 §4.3** · `PRD/HILiT_PRD_v0_2.md` **v0.4** AC7-1 · **AF-16**

> ### 🔴 SRS v3.2 반영 — 플로우가 한 방향 마법사가 아니게 됐다 *(2026-09-02)*
> PRD v0.3 **F29**가 대기 구간에 **옆으로 빠지는 길**을 낸다. 기존 설계의 *"5단계 마법사"* 전제가 여기서 흔들린다.
>
> | | v3.0 | **v3.2** |
> | --- | --- | --- |
> | 플로우 형태 | 업로드 → 컷 → 지정 → **추적 대기** → 선택 → … 한 방향 | 🔴 **대기 구간에서 피드로 빠졌다가 선택 단계로 복귀** |
> | 대기 중 사용자 | 플로우 안에 머문다 | 🔴 **플로우 밖으로 나간다 — 정상 경로다** |
> | "뒤로 가기 · 이탈 후 복귀" | 플로우 내부 문제 | 🔴 **앱 전역 문제** — 미니바(UX-014)가 복귀 경로를 갖는다 |
>
> 🔴 **"플로우 공통 — 단계 간 상태 연결" 항목의 범위가 넓어졌다.** 이제 *"뒤로 가기"* 뿐 아니라 **"피드에서 돌아왔을 때 어디로"** 를 함께 정의해야 하고, 그 답은 **서버가 들고 있는 `resume_route`** 다(FR-046).
>
> 🔴 **렌더 이후에는 이 길이 없다** — 이탈하면 소실되므로 진입점 자체를 만들지 않는다(R4).
>
> **기준 문서**: `SRS/[SRS]hilit-SRSv2.0-nextjs.md` **v3.2 §6.5.3** · `PRD/HILiT_PRD_v0_2.md` **v0.3** F29 · **FC-8** · **SD-9**

## 🎯 Summary
- 플로우명: **[UX-002] 편집 — 이미 찍은 영상에서 15초를 뽑아내기까지**
- 목적: **"긴 영상을 뒤지지 않게 한다"는 약속이 이 플로우에서 지켜지거나 무너진다.**

> 🔴 **§3의 이탈 분석이 이 플로우를 직접 지목했다** — *"④ 편집: 30분 초과 시 포기"* · *"지하철에서 한 손으로 30개는 많다"*.
>
> **탐지가 아무리 정확해도 고르는 일이 힘들면 2차 이탈이 그대로 재현된다.** 원본을 뒤지는 대신 목록을 뒤지게 된 것뿐이다.

## 🧪 설계 인수 기준

**항목 1: 앱이 갤러리를 만들지 않는다** *(REQ-FUNC-001)*
- 🔴 **OS 갤러리로 넘어간다.** 자체 그리드·날짜 그룹핑 화면을 설계하지 않는다

**항목 2: 코덱 거부가 막다른 길이 아니다** *(SC-1.F1)*
- 🔴 **"지원하지 않습니다"로 끝나지 않는다.** **어떻게 변환하면 되는지**가 화면에 있다. 없으면 사용자는 여기서 이탈하고 다시 오지 않는다

**항목 3: 재개가 재시작으로 보이지 않는다** *(SC-1.F3)*
- 🔴 **"이어서 올리는 중"임이 드러난다.** 진행률이 0%로 돌아간 것처럼 보이면 **재개 성공률 99%가 무의미**하다

**항목 4: 아무것도 선택되어 있지 않다** *(REQ-FUNC-005)*
- 🔴 **초기 상태 0개.** *"추천 5개 미리 체크"* 는 **자동 확정과 사실상 같다** — 사용자가 그대로 확정하면 시스템이 고른 것이 된다

**항목 5: 한 손으로 30개를 넘길 수 있다** *(§3 이탈 분석)*
- 🔴 **엄지 도달 범위** 안에서 스크롤과 선택이 모두 가능하다. 상단에만 조작이 있으면 이 화면에서 이탈이 발생한다

**항목 6: 개수가 바뀌어도 무너지지 않는다** *(A3 · Q7)*
- 15개일 때 허전하지 않고, 50개일 때 지치지 않는다. 🔴 **개수는 실측으로 정해질 값이므로 설계가 특정 숫자에 의존하면 안 된다**

**항목 7: 후보가 적을 때 이유가 있다** *(SC-1.F6)*
- 🔴 **"2개뿐"이 아니라 "28개는 확신이 낮아 제외했다"**가 전달된다. **이유 없이 짧은 목록은 탐지 실패로 읽힌다**

**항목 8: "잘 잡혔다"를 물어보고, 그것이 흐름을 막지 않는다** *(SC-3.1)*
- 🔴 **5점 척도가 화면에 있고 건너뛸 수 있다.** 묻지 않으면 SC-3.1의 80%를 측정할 방법이 없고, 강제하면 완주율이 떨어진다

**항목 9: 다시 고르기가 손실로 보이지 않는다** *(SC-3.F2 · ADR-3)*
- 🔴 **"기존 선택이 남아 있다"가 전달**된다. 처음부터 다시라고 느끼면 **아무도 누르지 않고 ADR-3 판정 데이터가 0이 된다**
- 🔺 **시각적 무게 조절** — 너무 숨기면 데이터가 안 모이고, 너무 강조하면 **재선택률이 인위적으로 올라 판정이 오염**된다

**항목 10: 세션 내 재업로드가 0건이다** *(SC-3.2)*
- 🔴 **재업로드 시도가 나온다는 것은 이 플로우가 "다시 고르기"를 전달하지 못했다는 뜻**이다

**항목 11: 음악을 건너뛰기 쉽고, 500곡을 다 보게 하지 않는다**
- 🔴 **곡을 고르지 않고 넘어가는 길이 명확**하다. 🔺 **500곡을 스크롤하게 만들면 여기가 새로운 이탈 지점**이 된다

**항목 12: 반입 경로가 없다** *(C3)*
- 🔴 **"내 음악 추가" 같은 입구를 설계하지 않는다.** 사용자 요청이 있어도 **저작권 리스크가 사용자 경유로 들어온다**

**항목 13: 음악 단계가 없어도 흐름이 이어진다** *(NF-016)*
- 🔴 **게이트 미승인 시 화면이 통째로 없다.** 그때 **선택 확정 → 렌더** 로 자연스럽게 이어지는 흐름이 설계에 있어야 한다

**항목 14 (경계): 편집 기능을 늘리지 않는다**
- 🔴 **원본 자르기·회전, 후보 구간 직접 조정, 수동 구도 조정은 요구사항에 없다.** 넣는 순간 *"30분 넘는 편집"* 이라는 이탈 지점을 되살린다

## ⚙️ 설계 제약
- 🔴 **선택은 명시적 조작이어야 한다** — 사용자가 누르는 "전체 선택"은 허용, 시스템이 미리 고르는 것은 불가
- 🔴 **저신뢰 후보는 목록에 없다**(REQ-FUNC-027) — **저신뢰 배지를 설계하지 않는다.** 제외된 것은 존재하지 않는다
- 🔴 **코덱 판정은 선택 직후 · 전송 전** — 흐름이 이 순서를 따라야 SC-1.F1의 *"GPU 작업 0건"* 이 성립한다
