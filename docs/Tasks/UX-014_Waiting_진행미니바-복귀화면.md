> ### 🆕 SRS v3.2에서 신설 *(2026-09-02)*
> PRD v0.3 **F29**가 대기 시간을 소비 시간으로 바꾸면서 생긴 화면. 🔴 **화면 하나가 아니라 앱 전체에 얹히는 층**이라, 기존 8개 UX 태스크와 성격이 다르다.
>
> **기준 문서**: `SRS/[SRS]hilit-SRSv2.0-nextjs.md` **v3.2 §6 · §6.5.3 · §6.5.5** · `PRD/HILiT_PRD_v0_2.md` **v0.3** F29 · ADR-6

> ### 🎨 이것은 구현 태스크가 아니다
> 산출물은 화면 설계이며 구현은 **FR-046**과 **FE-014**가 받는다.

## 🎯 Summary
- 화면명: **[UX-014] 상단 8px이 8분을 견디게 한다**
- 대응 요구사항: 🆕 **REQ-FUNC-033** *(구현은 FR-046)*
- 목적: **편집에서 피드로 나갔다가 돌아오는 길을, 소비를 방해하지 않으면서 잃어버리지 않게 만든다.**

> 🔴 **이 설계의 어려움은 "작아야 하는데 놓치면 안 된다"는 모순이다.**
>
> 미니바가 크면 **피드 소비를 방해**해서 F29가 풀려던 것(대기를 가치로 바꾸기)을 스스로 깬다. 작으면 **완료를 놓쳐** 사용자가 돌아오지 않는다(PRD R13). **이 둘 사이를 찾는 것이 이 태스크의 본체다.**

> 🔴 **UX-010(처리 진행 화면)과 이 화면은 다른 것이다.** UX-010은 **사용자가 대기 화면에 머물 때** 보는 전체 화면이고, UX-014는 **떠났을 때 따라오는 8px**이다. 🔴 **둘의 정보 위계가 같으면 안 된다** — 미니바에 UX-010의 내용을 축소해 넣으면 읽히지도 않고 자리만 차지한다.

> 🔴 **완료 알림 뒤에 아무 일도 일어나지 않아야 한다.** 보던 영상을 끊고 편집으로 튀는 설계는 ADR-6에서 **명시적으로 기각**됐다. 알리고 **기다린다** — 그 기다림이 이 화면의 가장 중요한 상태다.

## ✅ 산출물 (설계 항목)

### 1. 미니바 자체
- [ ] **정지 상태 시안** — 단계 라벨 + 퍼센트 · 🔴 **"추적 중 · 4/6 클립(67%)"** 처럼 근거가 함께
- [ ] 🔴 **높이·겹침 방식 결정** — **오버레이(영상 위)** vs **레이아웃 밀어내기**. 세로 영상의 가용 높이가 걸린다 *(DS A-8)*
- [ ] **단계 전이 애니메이션** — 🔺 부드럽되 **없는 진행을 그리지 않는다**
- [ ] 🔴 **`RECOVERING` 을 "추적 중"으로 묶는 표기** — 단계가 오락가락하면 멈춘 것보다 불안하다 *(ST-5)*
- [ ] 접기·숨기기 가능 여부 — 🔺 **숨기면 R13이 커진다.** 허용할지 결정
- [ ] 다크·라이트 / 세로·가로 대응

### 2. 진입 — 편집에서 나가는 순간
- [ ] 🔴 **컷 대기 안내** — *"창을 닫아도 계속됩니다"* + **피드 보러 가기** 진입점
- [ ] 🔴 **추적 대기 안내** — *"이 탭은 열어 두세요 · 다른 화면은 보셔도 됩니다"* + 진입점
- [ ] 🔴 **두 문구가 절대 섞이지 않는 배치** *(FC-8)*
- [ ] 🔴 **렌더 단계 — 진입점이 없는 상태** *(R4)* · 이탈 경고는 유지
- [ ] 진입점의 시각적 무게 — 🔺 **너무 강하면 이탈을 부추기고, 약하면 아무도 안 누른다**

### 3. 대기 중 — 피드 위에서
- [ ] 미니바가 **피드 조작(스크롤·탭·좋아요)을 가리지 않는** 배치
- [ ] 🔴 **저부하 모드가 사용자에게 어떻게 읽히는가** — 정지 이미지 모드에서 *"고장"이 아니라 "지금은 이렇게 보여준다"* 로 읽히게
- [ ] 🔺 **저부하 모드 고지 여부** — 알릴지, 조용히 할지. **알리면 품질 저하가 부각되고, 안 알리면 앱이 느리다고 오해받는다**
- [ ] 다른 탭(마이페이지·설정)에서의 미니바 상태

### 4. 완료 — 알리고 기다린다
- [ ] **완료 상태 시안** — 진행 → 완료로 바뀌는 순간
- [ ] **toast 1회** 문구·지속 시간 · 🔴 **모달 금지**
- [ ] 🔴 **알림 후 아무 일도 일어나지 않는 상태** — 사용자가 영상을 계속 볼 수 있다
- [ ] toast를 놓친 뒤의 **잔류 표시** — 🔴 **한 번 뜨고 사라지면 R13이 커진다**
- [ ] 🔺 **"완료되면 자동으로 돌아가기" 설정 UI** — 기본 OFF · 어디에 두는가
- [ ] 복귀 전환 — 미니바 탭 → 편집 화면 · **p95 ≤ 2초 사이의 로딩 상태**

- [ ] 🔴 **대기 중 탭 종료 후 재진입 화면** *(AF-14)* — *"4개까지 끝났습니다, 5번째부터 이어갑니다"*

## 🧪 설계 인수 기준

**항목 1: 8px이 8분을 견디게 한다**
- 🔴 **피드를 보는 동안 진행이 계속 눈에 들어온다.** 완전히 잊히면 완료 알림이 뜬금없어지고, 너무 크면 피드가 안 보인다

**항목 2: 퍼센트에 근거가 붙어 있다** *(PRD §4.3 F29)*
- 🔴 **단계명 없는 숫자가 없다.** *"67%"* 만 있으면 무엇의 67%인지 알 수 없고, **매끄럽게 차오르는 단일 막대는 거짓말**이다 *(UX-010 항목 8과 같은 규율)*

**항목 3: 컷과 추적의 안내가 다르다** *(FC-8)*
- 🔴 **"닫아도 됨"과 "탭은 열어 두세요"가 한 화면에 섞이지 않는다.** 하나로 통일하면 **둘 다 틀린 말**이 되고, 사용자는 추적 중 탭을 닫는다 *(AF-14)*

**항목 4: 렌더는 예외임이 드러난다** *(R4)*
- 🔴 **미니바는 뜨는데 나가는 길이 없다.** 사용자는 미니바를 한 번 신뢰하면 단계를 구분하지 않으므로, **경고 문구를 늘리는 것보다 진입점을 없애는 편이 확실하다**

**항목 5: 완료가 소비를 끊지 않는다** *(ADR-6)*
- 🔴 **보던 영상이 계속 재생된다.** 화면이 튀면 F29가 O7(재방문 루프)을 스스로 갉아먹는다

**항목 6: 완료를 놓쳐도 되찾을 수 있다** *(R13)*
- 🔴 **toast가 사라진 뒤에도 미니바에 완료가 남아 있다.** 한 번 뜨고 마는 알림은 **자리를 비운 사용자에게 아무 의미가 없다**

**항목 7: 실패가 성공과 같은 자리에서 온다** *(AF-15)*
- 🔴 **실패를 편집 화면에 들어가야만 알 수 있게 두지 않는다.** 피드에서 30분을 보낸 뒤 돌아와서 실패를 알게 되면 30분이 통째로 낭비다

**항목 8: 저부하 피드가 고장으로 보이지 않는다** *(§6.5.5)*
- 🔴 **정지 이미지 모드에서 "재생이 안 된다"가 아니라 "탭하면 재생된다"로 읽힌다.** 출시 기본값이 여기에 가깝다는 점에서 **이 상태가 실질적 첫인상**이다

**항목 9: 활성 작업이 없으면 흔적도 없다**
- 🔴 **빈 미니바를 남기지 않는다.** 상시 표시되는 빈 막대는 화면만 좁힌다

**항목 10 (경계): UX-010을 축소 복제하지 않는다**
- 🔴 **미니바는 단계와 퍼센트, 그리고 탭 가능 여부가 전부다.** 예상 시간·실패 상세·재시도 버튼은 **UX-010의 몫**이다. 8px에 다 넣으려다 아무것도 안 읽히게 만드는 것이 이 화면의 전형적 실패다

**항목 11 (경계): 대기를 늘리는 장치를 만들지 않는다**
- 🔴 **"조금만 더 기다리면 완성!" 같은 게이미피케이션·보상 배지를 설계하지 않는다.** F29의 목표는 **대기를 잊게 하는 것**이지 **대기를 즐기게 하는 것**이 아니다 — 후자는 대기 단축(§5.1)의 동기를 지운다

## ⚙️ 설계 제약
- 🔴 **`Dialog`(모달)를 쓸 수 없다** — 피드 소비를 끊는다. `Progress` + `Sonner` 조합 *(SRS §6)*
- 🔴 **단계별 행동이 다르다** — 컷·추적은 진입점 있음, 렌더는 없음, 선택은 대기가 아님 *(ST-5)*
- 🔴 **통합 퍼센트를 쓸 수 없다** — 단계 가중치가 `[TBD]` *(Q22)*. 설계가 단일 막대를 전제하면 Q22가 풀려도 못 쓴다
- 🔺 **출시 기본값이 정지 이미지 모드일 수 있다** *(§6.5.5)* — **저부하 상태를 예외가 아니라 기본으로 두고 설계**한다. 실측 후 완화되는 방향이지 그 반대가 아니다
- 🔺 **미니바 높이가 세로 영상 가용 높이를 줄인다** *(DS A-8)* — 오버레이/밀어내기 결정이 UX-001(앱 셸)과 충돌하지 않을 것
- 🔺 **접기 허용 여부가 R13과 직결** — 숨길 수 있으면 완료를 놓칠 확률이 오른다
