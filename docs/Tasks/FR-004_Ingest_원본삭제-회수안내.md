- 기능명: **[FR-004] 결과물은 남기고 원본만 지운다 · 지웠는지 물어본다**
- 목적: **완성 영상을 확보한 뒤 저장공간을 회수하고, 웹에서는 관측할 수 없는 O4를 자기신고로 대체 계측한다.**

> 🔴 **FR-024와 절대 같은 코드로 처리하면 안 된다.**

## 🧪 Acceptance Criteria (BDD/GWT)

**Scenario 1: 원본을 지워도 결과물이 살아 있다** *(제약 2)*
- **Given**: 완성 영상이 생성된 원본
- **When**: 원본을 삭제함
- **Then**: 🔴 **완성 영상이 그대로 재생된다.** `source_video_id` 가 `NULL` 이 되고 CASCADE로 함께 지워지지 않는다

**Scenario 2: 결과물이 없으면 그냥 지우지 않는다**
- **Given**: 아직 완성 영상을 만들지 않은 원본
- **When**: 삭제를 시도함
- **Then**: **되돌릴 수 없음이 안내**된다. 🔴 *"원본을 지우면 다시 만들 수 없다"* 는 사실을 알고 결정해야 한다

**Scenario 3: 다른 사람의 원본을 지울 수 없다**
- **Given**: 타인 소유의 `videoId`
- **When**: 삭제를 시도함
- **Then**: **거부된다.** 소유권 검증이 RLS와 애플리케이션 양쪽에 있다

**Scenario 4: 물리 삭제와 논리 삭제를 혼동하지 않는다**
- **Given**: 삭제 완료 상태
- **When**: 객체 스토리지를 직접 조회함
- **Then**: **원본 객체가 실제로 없다.** 목적이 **용량 회수**이므로 논리 삭제는 목적을 달성하지 못한다

**Scenario 5: 기록이 생긴 뒤에만 안내한다** *(REQ-FUNC-019)*
- **Given**: 렌더가 완료되고 기록이 저장됨
- **When**: 안내 조건을 확인함
- **Then**: 🔴 **이때 처음 안내가 뜬다.** **기록 생성 전에 안내하면 원본과 결과물을 동시에 잃는다**

**Scenario 6: 안내가 지울 대상을 특정한다**
- **Given**: 안내 화면
- **When**: 문구를 확인함
- **Then**: **어떤 영상인지 알 수 있다.** *"원본을 정리하세요"* 만으로는 갤러리에서 무엇을 지울지 모른다

**Scenario 7: 응답하지 않아도 흐름이 막히지 않는다**
- **Given**: 사용자가 1문항을 건너뜀
- **When**: 다음으로 진행함
- **Then**: 🔴 **정상 진행된다.** 지표 수집이 사용 흐름을 막으면 안 된다

**Scenario 8: 자기신고가 실측이 아님이 표시된다** *(O4)*
- **Given**: O4 지표
- **When**: 보고서에 표시함
- **Then**: 🔴 **자기신고임이 명시**된다. **관측값처럼 다루면 50% 달성 여부를 근거 없이 주장하게 된다.** `source_deleted`(서버)와 `origin_delete_reported`(단말)는 **서로 다른 값이며 합산하지 않는다**

**Scenario 9 (실패): 이 경로가 REQ-NF-019를 만족한다고 주장하지 않는다**
- **Given**: 정보주체가 삭제를 요구한 상황
- **When**: 이 함수만 호출함
- **Then**: 🔴 **요구가 이행되지 않는다.** 궤적·구간·후보·완성물이 남는다. **FR-024를 호출해야 한다**

## ⚙️ Technical & Non-Functional Constraints
- 🔴 **`SET NULL` 은 이 FK 하나뿐이다** — 다른 관계는 CASCADE다. **스키마에서 이 예외가 지워지면 이 기능이 무너진다**(CT-001이 지킨다)
- 🔴 **서버 원본 정리로 폰 용량 문제를 대체하지 않는다**(v2.2 §6.5.2)
- 🔺 **중간 산출물의 처리 범위가 `[TBD]`** — 궤적을 남기면 재편집이 가능하지만 용량 회수 효과가 줄고, 지우면 원본 없이 재편집이 불가능해진다. **결정 근거는 §6.3 결정 9**
- **O4 Target 50%는 `[HYPOTHESIS]`** · Baseline **미측정** — 이 태스크는 달성이 아니라 **측정 가능성**까지 책임진다
- 🔺 **SC-4.F2의 용량이 서버인지 단말인지 `[TBD]`** — 웹에서는 단말 용량을 알 수 없으므로 **서버 저장 할당량 해석이 유일하게 구현 가능하다**
- 🔺 **안내 빈도 `[TBD]`** — 매번 띄우면 피로하다
- 삭제는 되돌릴 수 없으므로 **확인 단계를 UI에 둔다**(FE 소관)
