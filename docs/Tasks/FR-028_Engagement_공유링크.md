## 🎯 Summary
- 기능명: **[FR-028] 링크로 공유해도 공개 범위가 따라간다**
- 목적: **앱 밖으로 나가는 유일한 경로에서 공개 범위가 새지 않게 한다.**

> ✅ **개정(T16) — 공유 링크도 로그인 경로다.** 링크를 열면 **가입·로그인을 거친 뒤** 기록으로 간다. 따라서 다른 모든 경로와 마찬가지로 **RLS가 신원을 아는 상태**에서 판정이 이루어진다.
>
> 🔴 **그래도 링크는 여전히 가장 약한 고리다.** 신원은 알게 되었지만 **링크 소지자는 팔로우 관계도 구성원도 아닌 임의의 로그인 사용자**이기 때문이다. 여기서 *"링크가 있으면 볼 수 있다"* 로 구현하면 **비공개 기록이 카카오톡으로 유통된다.**
>
> 요구 문구: *"공유 링크도 **기록의 공개 범위를 따라야 한다.** 비공개 기록의 링크는 **발급되지 않거나 접근이 거부**되어야 한다."*

> 🔺 **배치는 "없어도 동작하는" 종류다.** 접근 시점 판정이 만료를 확인하므로 배치가 없어도 **만료 후 접근 성공은 0건**이다. 배치의 역할은 **만료 토큰이 무한히 쌓이는 것을 막는 정리**다. 🔴 **그러므로 배치 실패가 보안 사고가 되면 안 된다.**

## 🧪 Acceptance Criteria (BDD/GWT)

**Scenario 1: 비공개 기록의 링크는 발급되지 않는다** *(REQ-FUNC-017)*
- **Given**: `visibility = private` 인 기록
- **When**: 공유 링크 발급을 시도함
- **Then**: 🔴 **거부된다.** 발급 후 접근 거부가 아니라 **발급 자체가 안 된다**

**Scenario 2: 발급 후 비공개로 바뀌면 링크가 죽는다** *(범위 승계)*
- **Given**: 전체공개 기록의 유효한 공유 링크
- **When**: 소유자가 나만 보기로 전환함(FR-020)
- **Then**: 🔴 **접근이 거부된다.** **발급 시점의 범위를 토큰에 굳혀두면 여기서 새어나간다** — 접근할 때마다 현재 범위를 본다

**Scenario 3: Private 기록의 링크는 소유자에게만 유효하다**
- **Given**: `visibility = GROUP` 인 기록의 공유 링크
- **When**: 비구성원이 링크를 엶
- **Then**: 🔴 **거부된다.** 링크 소지가 공개 범위를 대체하지 않는다

**Scenario 3-1: 미로그인 상태로는 볼 수 없다** *(✅ T16 신설)*
- **Given**: 전체공개 기록의 유효한 공유 링크
- **When**: **로그인하지 않은 사람**이 링크를 엶
- **Then**: ✅ **기록이 보이지 않고 가입·로그인으로 안내된다.** 인증을 마치면 **그 링크가 가리키던 기록으로 돌아온다**

> 🔴 **되돌아오는 동선이 없으면 이 결정은 링크를 죽인다.** 로그인 후 홈으로 떨어지면 받은 사람은 무엇을 보러 왔는지 잃는다.

**Scenario 4: 30일이 지나면 무효다** *(REQ-NF-012)*
- **Given**: 발급 후 31일이 지난 링크
- **When**: 접근함
- **Then**: 🔴 **만료 후 접근 성공 0건**

**Scenario 5: 회수가 60초 안에 반영된다** *(REQ-NF-012)*
- **Given**: 유통 중인 링크
- **When**: 회수함
- **Then**: 🔴 **60초 안에 접근이 거부**된다. CDN·캐시가 있으면 무효화 경로가 필요하다. **Cron 주기(시간 단위)로는 이 요구를 만족할 수 없다 — 회수는 동기 경로다**

**Scenario 6: Public → Private 되돌림이 링크를 회수한다** *(PRD AF-7)*
- **Given**: Public 기록의 공유 링크
- **When**: 소유자가 공개 범위를 Private로 되돌림
- **Then**: 🔴 **링크가 즉시 회수**된다(≤ 60초). **피드에서는 내려갔는데 링크로는 보이는 상태가 남으면 되돌림이 무의미하다**

**Scenario 7: 배치가 멈춰도 보안이 유지된다** *(REQ-NF-012)*
- **Given**: Cron이 며칠간 실행되지 않음
- **When**: 만료된 링크로 접근함
- **Then**: 🔴 **여전히 거부된다.** **접근 시점 판정이 1차 방어이고 배치는 정리일 뿐**이다

**Scenario 8: 배치가 실행 시간 상한을 넘지 않는다** *(A-T1)*
- **Given**: 정리 대상이 매우 많은 상황
- **When**: 배치가 실행됨
- **Then**: 🔴 **청크 단위로 처리하고 상한 안에 끝난다.** 남은 것은 **다음 주기가 이어서** 처리한다

**Scenario 9: Cron이 외부에서 임의로 호출되지 않는다**
- **Given**: Cron 엔드포인트 URL
- **When**: 인증 없이 호출함
- **Then**: **거부된다.** 공개 엔드포인트로 두면 누구나 배치를 유발할 수 있다

**Scenario 10 (실패): 공유 경로를 늘리지 않는다** *(REQ-FUNC-017)*
- **Given**: 앱 안 DM 같은 추가 경로 제안
- **When**: 범위를 검토함
- **Then**: 🔴 **명시적으로 범위 밖이다.** 링크 복사 · 카카오톡 · 문자 **셋으로 한정**한다

- 🔄 **v3.0** — 만료 상수가 **30일 하나**로 줄었다(그룹 초대 7일 삭제)

- 🔺 **`[PROPOSED]` 값들** — 30일 · 60초는 확정치가 아니다. **설정값으로 분리**한다
- ✅ **미로그인 접근 = 불허 (T16 확정)** — `[TBD]` 해소. 링크 열람에 인증을 요구하고, **인증 후 원래 링크로 복귀하는 동선**이 함께 필요하다. 🔴 **REQ-FUNC-017은 카카오톡 전달을 전제하므로, 이 결정은 그 전제와 긴장 관계에 있다** — 받은 사람의 이탈이 늘어나는 것이 감수한 대가다
- 🔺 **Cron 실행 주기 `[TBD]`** · **다른 정리 작업과의 통합 여부 `[TBD]`** — Cron 엔드포인트를 여러 개 두는 것보다 하나에 모으는 편이 A-T1 관리에 유리하다
